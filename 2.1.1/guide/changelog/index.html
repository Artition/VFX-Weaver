    Guide changelog¶

    This page is the authoritative record of guide revisions (vN): each entry describes how the documentation changed. A guide revision is not a mod version — the two numbers are independent, and released mod versions are recorded on the mod Changelog instead. Where a guide revision shipped with a release, the entry says so (for example v47 — released as 2.0.0).

    Current guide revision: v70. Mod version it documents: 2.1.1. Which jar to download is in the download table.

    v70 — released as 2.1.1¶

    • volume: "aura" on a GLSL-plugin leaf: the soft edge is smooth now, and the field contract is written down. The page now describes what the march actually does: a Lipschitz cone-envelope of the samples (continuous in screen space, exact for creased max/min fields, never thinner than the truth), false-position for the entry distance, and a near-miss that fades over the leaf's softness instead of a hard zero. That is the 2.1.0 fix for the banded ramp and the ~0.5 coverage cliff a wide soft volume showed (reported against 2.1.0 by the Void developer; the numbers live in scripts/check-mask-aura-softness.ps1, which ports their fixture). The page also states the one hard obligation on a plugin field — it must be a conservative distance, |grad d| <= 1, and C1 smoothness is explicitly not required — and the new VFXAPI.registerMaskShapeGlsl(id, plugin, lipschitz) overload for a field that is perturbed. API gained the same note. No datapack field renamed, no UBO/Config change, PROTOCOL_VERSION unchanged. Not verified in game (the owner tests it); the GLSL cannot run headless here, so the static contract is asserted by the runnable check and the owner checks visually.

    v69¶

    • A mask applies to post effects only, and the page now says so plainly. The mask coverage is a screen-space texture consumed by the post chain, so the world overlays — pulse_ring, light_beam, guide_line, particles, block_chain, block_tint, block_outline and the entity effects — never read it: a mask on one of them parses and then does nothing, with no error and no effect on the geometry (for the five geometry-only overlays the coverage prepass even runs and is never read). masks states this up front and points to the overlays' own spatial params (radius, thickness, intensity, region, pos_x/y/z) as the way to confine one, and the format block table mirrors it. Documentation only — no datapack field, UBO or wire change. Also corrected: the guide revision shown on the docs home and in this guide's index was still v67 after the v68 bump.

    v68 — released as 2.1.0¶

    • The showcase media set is complete. The clips recorded for the release are embedded on the pages that previously described their demos in text only: the sky/dome masks and the three plugin-mask demos on masks, the texture variant and the three sky anchors in Variants on sky_pattern, and a new Variants section for the two aim forms on light_beam. The showcase datapack zip was also rebuilt: the published one stored its entries with backslash separators, which a Java consumer cannot resolve, so the downloaded pack resolved to a single oddly named entry and every effect in it was silently missing.
    • film_grain: chroma, and the noise fixes. The page documents the new chroma parameter (0 monochrome, default; 1 coloured) and the re-recorded clip shows the centred cell grid, the non-repeating hash and the chroma ramp. That clip is the one noise asset in the set, so it is encoded at 30 fps / crf 30 (7 MB) instead of the pipeline default, which produced 19.9 MB.
    • pixelate and film_grain now measure their cell grid from the screen centre, so an animated cell size grows the pattern outwards from the middle instead of out of the bottom-left corner. Behaviour only — no field changed; per-scanline effects were left alone.

    v67¶

    • sky_pattern anchor: "stars" is now a real lock, not an approximation. The v62 stars anchor drove dome_rotation, a world-Y spin, while vanilla draws the star sphere with the pose Ry(-90°) · Rx(starAngle) (verified with javap in SkyRenderer.renderSunMoonAndStars on 26.2, 26.1.2 and 1.21.11), so the pattern turned about a different axis than the stars. The sky shader now takes the sampled direction into the star sphere's own frame with the exact inverse (include/dome.glsl: vfx_star_local_dir), gated on a new internal anchor_stars field, so a stars pattern is rigidly attached to the star material as it rotates. dome_rotation is not hijacked: it stays the author's world-Y spin, applied first, and sun/moon/dome are untouched. Two internal Config floats (anchor_stars, star_angle) are appended after sky_mode (no earlier std140 offset shifts); no datapack field renamed, PROTOCOL_VERSION unchanged. See sky_pattern. Not verified in game (the owner tests); scripts/check-sky-pattern.ps1 now asserts the shader's star-local transform is the exact inverse of the verified vanilla pose (a runnable round-trip over several angles and directions) and that the CPU passes the angle.
    • A built-in world GLSL mask plugin (vfxweaver:blobs_glsl), and the three plugin demos now use it. The only shipped GLSL plugin was vfxweaver:ringed_glsl, a screen-space 2D figure, so the space: "world" aura/surface demos rendered nonsense and the dynamic-data demo could not show the data driving anything (ringed_glsl ignores vfx_mask_data). The new built-in vfxweaver:blobs_glsl is a genuine world-space SDF (a union of up to eight spheres, negative inside): sphere k takes its centre/radius from consecutive vfx_mask_data entries (d[4k..4k+3]) and the leaf's p0..p7 are global controls (offset, radius scale/bias, count), with an optional vfx_shape_custom_bounds() broad phase over the same data+params extent so the aura march is cheap. The coverage shader now publishes the calling leaf's p0/p1 as vfx_shape_params0/vfx_shape_params1 (declared outside the injection markers, so an older plugin is unchanged) so the bounds can stay conservative. vfxweaver:ringed_glsl stays the screen reference. The three demos were rebuilt on it — show_mask_custom_glsl_aura_demo (a real filled volume, camera outside), show_mask_custom_glsl_surface_demo (geometry only; the sky is never painted) and show_mask_custom_data_demo (animated mask.p0.d<J> so the spheres visibly move). The plugin leaf shape is inert on the 1.21.11 node (no shader-source hook). Additive: no existing pass's UBO/wire layout changes, PROTOCOL_VERSION unchanged. See masks. Not verified in game (the owner tests); scripts/check-mask-world-plugin.ps1 asserts the registration is a WORLD plugin, the SDF reads the data, the bounds is present and reads the data, and aura/surface masks and all three demos parse.

    v66¶

    • fog_modifier: the hook moved to vanilla FogRenderer.setupFog's return (fix + doc). The effect now mutates the fog instance the game produces in place at setupFog's return, before any consumer reads it, so the distance scales and the colour reach the fog uniforms, the level renderer and the sky/cloud shaders together. The previous hook on updateBuffer(FogData) substituted a new instance for the parameter only, while the caller kept reading the original instance — the distance change never reached the horizon band and looked invisible. The param surface, the maths and the datapack format are unchanged (no field renamed, no UBO/shader change, PROTOCOL_VERSION unchanged); the 1.21.11 path keeps the private @ModifyArgs on the six distance slots and adds a return hook for the caller-visible colour. The mixin runs at priority = 900 so it injects before Sodium's fog mixin. Documented: the new hook point, and that the zenith keeps the dimension's own sky colour (the sky shader fogs ColorModulator toward the fog colour and only the far horizon reaches it). See fog_modifier. Not verified in game: the visual result (the owner tests); the hook point was proven with javap against each node's real jar, and scripts/check-fog-modifier.ps1 asserts the per-node hooks (26.x @Inject at setupFog's return mutating the returned FogData in place; 1.21.11 @ModifyArgs slots plus the return colour hook), priority = 900 and the combination maths runnably.

    v65¶

    • fog_modifier: a smooth transition from the vanilla fog colour (fog_color_amount), and the sky/cloud ends follow fog_end_scale. New optional fog_color_amount (0..1, neutral 1/unset, unauthored) scales the instance's colour weight: 0 leaves the colour completely untouched (the colour is not written at all and hasColor stays false), 1 is the full authored colour (today's behaviour) and in between is a partial blend. Because it is just a weight on the one order-independent weighted average (weight·fog_color_amount per effect) there is no second blend stage and the distance maths is unchanged; the final colour is vanilla + (target − vanilla)·min(1, Σ(w·amount)), clamped, and NaN never leaks. Author a constant fog_r/fog_g/fog_b and keyframe fog_color_amount from 0 to 1 to ramp from the dimension's own fog colour to the authored one and back — the smoothness the all-or-nothing colour could not give. Also documented (the code was already corrected before this revision): the sky/cloud fade ends (FogSkyEnd/FogCloudsEnd) scale with fog_end_scale, so fog_end_scale < 1 pulls the wall in and narrows the horizon band and brings the clouds closer; they have no start value, so fog_start_scale never touches them. Additive and backward-compatible: a new param only, absent = the full authored colour, no datapack field renamed, no shader/UBO change, PROTOCOL_VERSION unchanged, no new dependency. See fog_modifier. Not verified in game: the visual ramp and the distance look (the owner tests); scripts/check-fog-modifier.ps1 asserts the colour-amount maths runnably (amount 0/0.5/1, unauthored = 1.0, order-independent, no colour write at 0) and the per-node hooks statically.

    v64¶

    • fog_modifier: change the vanilla fog at its source. A new effect, the fog sibling of fov_modifier and deliberately not a post pass: fog_start_scale/fog_end_scale multiply the vanilla fog start/end distance (neutral 1.0; >1 sees further, <1 pulls it closer) and optional fog_r/fog_g/fog_b override the fog colour (neutral = unset). The mod rewrites the values vanilla serialises into the fog uniforms, so vanilla terrain/entities and the entity-effect geometry all see it; absent params leave the fog untouched. Scales combine additively around neutral and colour is a weight-averaged blend from vanilla (order-independent, clamped). Coverage: every distance-based fog on 26.2/26.1.2/1.21.11 — overworld, the nether (fog_start_distance 10 / fog_end_distance 96 in its dimension definition) and the End, plus water/lava/snow/blindness/darkness. The design warned the nether/end might be density-based; it was checked and is not on these nodes — FogData has no density field and EnvironmentAttributes has no density attribute on any of the three, and the dimensions express fog as start/end distances, so the scales are the complete control. Honest limits (stated in the page): under an Iris shaderpack the effect is a no-op (a pack computes its own fog and ignores the vanilla values); the sky/cloud fade distances are not touched; and the block_tint/block_outline/glow/spark overlays use the fog-free core/position_color shader, so only the entity-effect pipelines inherit the change. No shader change, no UBO change, PROTOCOL_VERSION unchanged, no new dependency. See fog_modifier. Not verified in game: the visual result (the owner tests); the write point was proven with javap against each node's real jar, and scripts/check-fog-modifier.ps1 asserts the type/neutral/isPostProcessing wiring, the manager accumulation, the per-node target and the combination maths runnably.

    v63¶

    • sky_pattern drops the legacy equirectangular dome mode. The effect is unreleased, so the single global chart is removed rather than kept as a legacy path: patch is renumbered to 0 (default) and fill to 1, and "dome" - or any other unknown value - is now a per-file parse error naming the accepted values. The reason is stated plainly in the page: a single global chart of a sphere has a pole singularity and a mandatory seam - topological, not fixable - so there is no equirectangular mode; a true skybox cube (six authored faces) remains a separate future feature. vfx_dome_uv stays in include/dome.glsl for the space: "dome" mask path (the mask is untouched). The built-in sky_pattern and every sky demo use only patch/fill. No new shader field, no UBO/Config change, PROTOCOL_VERSION unchanged. See sky_pattern. Not verified in game: the GLSL cannot run headless here - the static contract is asserted by scripts/check-sky-pattern.ps1 and the owner checks visually.

    v62¶

    • sky_pattern can follow the sun, the moon or the stars. A new optional top-level anchor field: omitted (or "dome") keeps today's world-fixed anchor_yaw/anchor_pitch; "sun" and "moon" make the pattern track the vanilla body; "stars" locks the pattern to the rotating star sphere by driving dome_rotation from the star angle. The body angles are read from the client's own sky render state on the CPU and written to the same three uniforms, so there is no shader change and no mixin — this is what makes the anchor work under Iris: the pack may draw the sky itself, but the world time (and so the angles) is still computed by the game. Fail-closed: if the sky state cannot be read (no overworld sky, or the render state is not ready this frame) the effect contributes nothing rather than painting at a guessed spot, and reports once through the logger. Honest limits, stated in the page: the effect is an overlay, so the vanilla sun/moon stay drawn underneath (size the pattern to cover them — sun ≈33° apparent width, moon ≈24°); and the vanilla star colour cannot be changed without a SkyRenderer mixin, so "stars" places a pattern at the star sphere rather than recolouring the vanilla stars. Two further design items are deliberately not implemented because they would be Iris no-ops: a SkyRenderer mixin to draw under the vanilla bodies (S4b) and a frame-graph sky-capture pass (S5). Additive: a new top-level field only, no datapack field renamed, PROTOCOL_VERSION and every UBO layout unchanged, and the effect is not in a release yet. See sky_pattern. Not verified in game: the anchor's exact tracking and its look under an Iris pack (the owner tests visually); the shipped scripts/check-sky-pattern.ps1 asserts the parse, the resolver and the angle→yaw/pitch maths runnably, and the per-node sky-state access was proven with javap on the real jars.

    v61¶

    • A patch has no built-in clip, and the ring demo no longer circles the player. The v60 unit-disc bound was removed - the owner tested it and rejected it (the circular clip visibly cut the figure; the earlier unbounded behaviour was not a defect to them). A patch is a flat sign on the tangent plane with no built-in clip: it runs out to the tangent-plane horizon and a pixel behind the decal (dot(dir, anchor) <= 0) is discarded as a hard backstop. A large patch can show that horizon as a straight cut - the rule is the developer who needs a clean edge adds a mask. tile_scale is documented as the cell scale on that plane (the half-angle table is gone), and the demos keep the v60 sky_mode reassignment (show_sky_pattern_texture and sky_cracks are fill; show_sky_pattern and nine_red_pixels are small patch decals). The show_sky_pattern ring demo no longer animates dome_rotation: in patch mode that spins the sampled direction before projection and carries the decal along its latitude, so it circled the player; the demo now animates only tile_scale and opacity, which leave the anchor fixed, and the docs state the semantics (dome_rotation locks a decal to the rotating star sphere, the in-plane rotation spins the figure in place). No datapack field renamed, no UBO/Config change, PROTOCOL_VERSION unchanged. See sky_pattern. Not verified in game: the GLSL cannot run headless here - the static contract is asserted by scripts/check-sky-pattern.ps1 and the owner checks visually.

    v60¶

    • patch decals are bounded to a clean disc, and the demos use each sky_mode for what it is for. The gnomonic patch decal divided by dot(dir, anchor), so its tiling frequency grew without bound as the ray approached the tangent plane's horizon and the old facing gate cut the decal off with a hard straight edge - a large patch read as a flat plane lying over the sky with a smear at its rim. patch now bounds the decal to its unit disc: tile_scale is the patch's angular half-size, tan(half angle) (0.27 ≈ 15°, 0.45 ≈ 24°, 0.577 = 30°, 1.0 = 45°), radius 1 is the patch edge, the coverage fades to zero at the rim (over softness, min 0.05 cell units) and nothing is evaluated past radius 1, so the singular rim is never visible. The honest limit is documented: the decal is a flat sign (one tangent plane), so it does not follow the dome's curvature - use fill for content that must wrap the whole sky. The demos were reassigned: show_sky_pattern_texture (a whole-sky texture) and sky_cracks are fill, while show_sky_pattern (the ring) and nine_red_pixels are small bounded patch decals (tile_scale 0.4-0.55 and 0.3). Additive and backward compatible: no datapack field renamed, PROTOCOL_VERSION and every UBO layout unchanged, and the effect is not in a release yet. See sky_pattern. Not verified in game: the GLSL cannot run headless here - the static contract is asserted by scripts/check-sky-pattern.ps1 and the owner checks visually.

    v59¶

    • sky_pattern gains a sky_mode projection and stops funnelling at the zenith. The first release projected the whole dome through one global equirectangular chart, which has two topological defects: u is undefined at the poles (tiling there has infinite frequency, so the pattern winds into a funnel at the zenith - where players look) and u must wrap at ±180° yaw (a visible seam / mirror axis). sky_mode replaces the addressing with an atlas of local charts plus a smooth partition of unity: patch (default) is one gnomonic (tangent-plane) decal at the anchor - no pole, no seam, clean discard past the decal horizon, keep tile_scale <= 1.0; fill covers the whole sphere with three orthographic charts blended by a sharpened partition of unity - no pole convergence and no seam anywhere, with coverage and colour blended (never the UVs) and the colour renormalised so texels stay saturated in the ~±8° crossfade ribbons, density varying up to ~1.7x; and dome is the legacy equirect path, kept byte-for-byte, with its inherent pole funnel and north seam, not for new content. The anchor is a position in patch and a tiling phase shift in fill; dome_rotation spins the whole field. Additive and backward compatible: sky_mode is appended last to the Config UBO, no existing shader's layout changes, no field renamed, PROTOCOL_VERSION unchanged, and the effect is not in any release yet, so the new default (patch) breaks nothing. A full skybox cube remains a separate future feature. See sky_pattern. Not verified in game: the new projection maths (the owner tests visually); the static contract is asserted by scripts/check-sky-pattern.ps1.

    v58¶

    • sky_pattern: a datapack figure or texture painted on the sky dome. A new screen post effect (stage S3 of the skybox design) and the sky sibling of surface_pattern: the same structural pattern block, shape library and pattern.texture addressing, but the projection target is the dome. The pixel's view ray is reconstructed, optionally spun about world Y by the new dome_rotation param, and mapped to an equirectangular dome coordinate, where the figure is placed by the new anchor_yaw/anchor_pitch params (degrees). The whole pass is gated on the depth sky test, so it only ever paints far-depth sky pixels - never terrain, the hand or the GUI. repeat: [3, 3] gives nine dots with no texture; a pattern.texture with a sheet and the animatable frame param gives an animated sky. Additive: a new effect type only, no existing effect changed, no field renamed, PROTOCOL_VERSION unchanged, and no existing shader's UBO layout touched (the new sky_pattern Config adds a vec4 cam_pos the other depth pass does not have). See sky_pattern. The dome's pole pinch and the u wrap seam are inherent to equirectangular; the far-depth gate uses the same in-game-verified test as the sky mask. Not verified in game: the rendering itself (the owner tests visually), and the effect under an Iris shaderpack (a post pass composes over the pack's sky, as with every other post effect).

    v57¶

    • light_beam can end on a chosen point. Three optional params — end_at_x/end_at_y/end_at_z — name the world point the far end of the beam lands on. The anchor is then derived as end − axis × height, so the geometry finishes exactly at the point (with the default axis it hangs straight down from height above it — a beam falling out of the sky). They are ordinary animatable params (keyframes, expr, graph, bind), and a beam from A to B is end_at = B plus the axis and length computed between the two points. Unset, the beam is unchanged. No shader, pipeline, UBO or wire change. See light_beam.

    v56¶

    • The sky mask confirmed in game, plus two things it does and does not cover. The far-depth assumption behind sky/space: "dome" is now verified in game on all three lines (26.2, 26.1.2 and 1.21.11), not just built from the convention. Two clarifications from that testing: the sun, the moon and the clouds are drawn without writing depth, so a sky/dome leaf covers them exactly like the empty sky — a recoloured sky recolours the sun and moon with it (to sit under the celestial bodies, the planned sky_layer selector is needed); and the horizon fog is baked into the terrain pixels, so a sky mask does not recolour it and a strong tint can leave a seam at the horizon. See Masks.

    v55¶

    • light_beam points in any direction. Three new params — dir_x/dir_y/dir_z, defaults 0/1/0 — set the beam axis, replacing the fixed vertical one, so a beam can be aimed at an angle (e.g. from a point on the sky). They are ordinary animatable params (keyframes, expr, graph, bind), including to the camera look via {"bind": "look_x"}/look_y/look_z. With the defaults the emitted geometry is unchanged, and a zero direction falls back to straight up. No shader, pipeline, UBO or wire change. See light_beam.

    v54¶

    • Sky masks: the sky leaf and space: "dome". A mask can now target the sky instead of the world. sky covers the whole visible sky (no parameters); a 2D shape (circle/ellipse/rect/polygon) with "space": "dome" is placed on an equirectangular map of the sky, with center authored as [yaw, pitch] degrees (yaw 0 = south, 90 = west, ±180 = north; pitch -90 = up, 0 = horizon, 90 = down) and radius in dome units where 0.5 spans half the dome. Both need depth (the sky test is the depth test) and both fail closed to zero coverage without trustworthy depth. A dome leaf is sky-occluded by construction, so geometry occupying a dome direction is never tinted — unlike a world leaf, which classifies geometry, and a screen leaf, which can cover anything. A dome center must be a literal [yaw, pitch]; a bound centre is a parse error for now, a sky leaf may not be screen/world, and dome space accepts only the 2D shapes and sky. The far-depth test is verified on 26.2; on 26.1.2/1.21.11 it uses the same proven per-node convention but is not yet confirmed in game. No wire, UBO or Java API change. See Masks.

    v53¶

    • A GLSL mask plugin leaf can be a volume, and a surface custom leaf no longer paints the sky. A world custom leaf registered through VFXAPI.registerMaskShapeGlsl now accepts "volume": "aura": the pixel's view ray is sphere-traced through the plugin's own SDF and the volume is filled — air and sky included — wherever the scene does not occlude it, using the same silhouette, edge fade and occlusion maths as a built-in sphere/box aura. A composed custom leaf (no raw SDF to march) and a screen-space plugin leaf are per-file parse errors that name the reason, never a silent fallback. A plugin may declare an optional vec4 vfx_shape_custom_bounds() (world centre and radius) as an analytic broad phase, so a ray that misses the volume is rejected without evaluating the SDF and the cost follows the volume's screen area; the march covers the first chord only, and a 0.5-block minimum step caps its reach at roughly 30 blocks. In the other direction, the default surface mode now gates the sky for custom leaves: a sky pixel contributes no coverage, so an intentionally unbounded plugin SDF no longer paints it (built-in shapes already behaved that way). An existing plugin that declares neither function compiles and behaves exactly as before; no wire, UBO or Java API change. See Masks and the Java API.

    v52 — released as 2.0.2¶

    • Mod version 2.0.2. The dynamic mask float-data feature documented in v51 ships as 2.0.2, together with the raised network parameter cap and the coverage UBO growth it required (see v51). No guide behaviour changed in this entry; only mod_version and the version wording moved. The full list is in the mod changelog.

    v51¶

    • GLSL mask plugin shapes can read live per-leaf float data, so their geometry changes without a shader recompile. A custom mask leaf now carries 32 reserved dynamic floats (mask.p<N>.d0 … d31), authored as a "data": [ … ] array or set every tick with the new VFXAPI.maskData/sendMaskData (or setParam/sendSetParam on a single mask.p<N>.d<J>). A plugin reads its own leaf's slice through the wrapper helper vfx_mask_data(vfx_shape_data_base + j), so one plugin source drives a moving set of primitives far past the eight animatable params. The coverage UBO gains a vec4-packed shape_data array (18 fields, 2336 bytes; appended after every existing field). Backward compatible: an existing plugin that ignores the helper compiles and behaves exactly as before, and a data update is an ordinary param edit that never recompiles the variant (keyed only by the plugin-id set). The wire param cap (VFXTriggerPayload.MAX_PARAMS, VFXTimeline.MAX_OVERRIDES) and the Flashback snapshot cap are raised 32 → 256 to fit a large mask's params; PROTOCOL_VERSION is unchanged, but the cap is read-side, so a 2.0.1 client still caps at 32 and needs a 2.0.2 client for a many-slot mask. A mask's custom leaves may reference only one distinct GLSL plugin id (two different plugin ids in one mask fail to compile and fall back to neutral coverage), and on 1.21.11 the missing shader-source hook leaves a GLSL-plugin shape inert. See Masks and the Java API.

    v49¶

    • An effect another mod triggers through the API is removed when a replay is scrubbed back past its trigger, and a played effect no longer flashes for a single frame. A play that reached the effect loop without being recorded into the replay (a network trigger or a client-local API play while a replay was open) used to be owned by nobody, so a backward scrub left it running. A seek now stops every active instance and re-places only the effects whose recorded trigger is at or before the new time, so a scrub back before its trigger removes it - finite, looping or persistent alike - without dropping anything between seeks (the earlier per-frame removal made the replay's own effect disappear after one frame).     v48¶

    • Looping and persistent effects are recorded into Flashback replays. This is what makes a looping showcase such as vfxweaver:graph_demo or vfxweaver:graph_logic_demo reproduce in a replay. See Flashback compatibility.

    • Mod version 2.0.0. Everything accumulated since v32 — guides v33–v46: value graphs and macros, per-pixel fields, masks with block geometry and GLSL-plugin shapes, surface_pattern with textures/faces/bands/stitch, spark particles and /vfx stop [<player>], plus per-line scene depth — ships together as 2.0.0.     v46¶

    • Textured surface_pattern now resolves on 1.21.11 (and on 26.1.2/26.2 without the first-frame abort). The texture resolver was written inside a >=26.1 guard with a neutral fallback for the 1.21.11 node, so once the depth pass started running there the texture never resolved, tex_flags never reached the RESOLVED bit and every textured projection drew nothing (the built-in procedural figure still worked). The resolver now has a real per-node implementation — 26.2/26.1.2 through the sprite AtlasManager (SpriteId keyed by TextureAtlas.location()), 1.21.11 through the remapped model AtlasManager and TextureAtlas.getSprite — funnelling every source form (block/item/atlas/standalone) through one resolved(...) factory that sets the flag bit. A standalone texture is shared by both nodes. See surface_pattern.
    • The surface_pattern std140 layout guard no longer aborts the post layer. The registration-time guard queried glGetUniformIndices with block-qualified names (Config.tile_scale); a driver that reports only the bare member name returned -1, which was then passed to glGetActiveUniformsiv (GL_INVALID_VALUE) and threw out of execute, so the first frame of a textured pattern failed with "Failed to apply VFX post-processing". It queries the bare member name first with a qualified fallback, skips members the driver does not list, and logs at ERROR without throwing, so a false positive cannot drop a frame.

    v45¶

    • Scene depth works on every supported line, not just 26.2. surface_pattern, the depth/world field functions and the depth-needing mask families (a world leaf, an aura volume, a block leaf's occlude) used to be gated to 26.2 because the world reconstruction assumed 26.2's reversed depth. The per-node depth convention is now proven from the client jars and injected into one shared shader source: 26.2 is reversed (glClipControl(GL_LOWER_LEFT, GL_ZERO_TO_ONE) — near = 1, far = 0) and 26.1.2 / 1.21.11 are standard (near = 0, far = 1). The shader converts the raw sampled depth, picks the correct sky test and the correct block-occlusion comparison per node, so a depth-needing effect now renders on 26.1.2 and 1.21.11 as well. Fail-closed is unchanged where no trustworthy depth exists. See surface_pattern and Masks.

    v44¶

    • surface.stitch — opt-in planar (top-down) projection. A new boolean in the structural surface block (default false). With "stitch": true every face samples the same top-down coordinate p = world.xz, so a wall pixel (x, y, z) shows exactly what the floor pixel at the wall base (x, floor_y, z) shows — the image's row at the wall line extruded vertically (a ring reaching a wall becomes two vertical stripes from its crossing points). The seam is continuous for any anchor height (the anchor's Y no longer matters), and min/max become a height slab that bounds how far up the wall the image stretches. A ceiling is excluded (a top-down projection cannot light a down-facing surface). Deliberate trade-off: a wall shows a 1D slice (vertically constant colour columns), not a 2D unwrapped image. Additive and off by default — without it the hard floor/wall plane switch is unchanged, so every existing definition and the built-in render exactly as before. See surface_pattern.
    • normal_mask: 1.0 coverage is no longer noisy. The 1.0 fallback compared the raw depth-derived normal against exactly 1.0, which a normalized normal numerically almost never reaches (0.9999…), so coverage flickered at the threshold (worst at grazing angles near the floor). It now tests the snapped normal (abs(n.y) >= 0.5), which is exact for an axis-aligned block face.

    v43¶

    • /vfx stop [<player>] stops every active effect of a player. With no argument it stops all of the executing player's effects; with a player (selector) it stops that player's effects. It reuses the existing per-effect stop payload on the server and, for the executor's own client, also clears effects played locally (single player / a client-only mod). The old /vfx stop <effect> [players] form is unchanged: a bare token is parsed as an <effect> first, so use a selector (@p/@a) to target a player. New VFXAPI.sendStopAll(ServerPlayer).
    • Mask depth gate is consistent across nodes. depthRecipeVerified() was left in the 26.2 Stonecutter form on disk, so the active 26.1.2 Fabric node compiled return true while every other node (including 26.1.2-neoforge and 1.21.11) compiled false. The active-node form is now the false branch, so a depth-needing mask fails closed (zero coverage) on every non-26.2 node, as documented, instead of silently using the unverified reversed-depth recipe on Fabric.
    • A screen-only mask renders on nodes without the verified depth recipe. The coverage prepass bound the coverage target's own colour texture as the DepthSampler placeholder when depth was untrusted (a feedback loop, undefined on some drivers); it now binds the main target's depth view (else its colour view), so a mask that needs no depth renders identically on 26.2, 26.1.2 and 1.21.11.

    v42¶

    • surface_pattern now requires 26.2 (it no longer silently passes through on 26.1.2). The pass is registered on >=26.2 only, matching the mask coverage gate: the reversed-depth reconstruction it reads was verified on 26.2, while 26.1.2/1.21.11 use the other depth convention. On a non-26.2 node the effect type and JSON still parse, but no pass is registered and the effect draws nothing (previously 26.1.2 rendered a passthrough with a one-time warning). See surface_pattern.
    • The effect clock and camera/player snapshots are refreshed before layer 0. They used to advance in the FogRenderer.endFrame hook, which runs after renderLevel, so a surface_pattern (default screen_layer: 0) trailed the player by a frame and time-driven animation was a frame late. Layer 0 now advances the clock and republishes the snapshots; layers ½ reuse them, and nothing advances twice. See surface_pattern.
    • normal_mask: 1.0 is no longer undefined. The degenerate smoothstep(normal_mask, min(normal_mask + 0.2, 1.0), …) edge collapse (undefined in GLSL) is guarded by clamping normal_mask to 0..1 and falling back to the exact hard test at 1.0.
    • A band_softness wider than the band is clamped to half the band width, so a narrow band (min:10, max:10.5) is solid at its centre instead of evaluating to ~0.28.
    • distort warps a flat surface instead of translating it. Its phase was dot(world, normal), constant on any flat axis-aligned surface; it now follows the in-plane coordinate. Definitions with a non-zero distort on a floor see a different (intended) result.
    • Parse fixes that stop a definition from silently doing nothing. An empty faces: [] is now a parse error; pattern.center_x/center_y/center_z are rejected (use pattern.center); an entity-anchored positions entry on a surface_pattern is rejected; a pattern.texture.id/atlas with invalid id syntax is a per-file parse error.
    • Per-frame work in the post chain is reduced — one definition lookup per surface_pattern pass instead of three, and the texture id is parsed once at definition-parse time instead of every frame.

    v40¶

    • Textured surface_pattern figures — the structural pattern block accepts an optional texture object: a real texture (a block-atlas sprite, an item-atlas sprite, any atlas sprite, or a standalone resource-pack texture) projected onto the same surface the figure uses. id is required; source (block/item/atlas/standalone) is inferred from the id when omitted; channel (alpha default, luminance/r/g/b), sheet ([cols, rows], 1..16, cols*rows <= 256) and aspect (preserve/stretch) are optional. The texture is the figure and an authored figure becomes its mask (a texture with no figure is not clipped). New animatable params rotation (overrides the structural rotation), frame (sprite-sheet cell) and texture_tint (0..1 recolour).     v39¶

    • surface_pattern surface selection — an optional top-level structural surface block selects which face orientations receive the pattern (faces: up/down/north/south/east/west, axis aliases x/y/z, groups horizontal/vertical/all) and an optional inclusive band (min/max) applied along the fragment's dominant axis (Y for up/down, X for east/west, Z for north/south).     • surface_pattern band edge is no longer hard — a surface lying exactly on a band min/max bound flickered, because the depth-reconstructed axis coordinate jitters across the inclusive test from pixel to pixel. The optional band_softness (blocks, 0..4, default 0) fades the band edge over a small world-space distance, keeping the interior fully on and the outside fully off; 0 is the exact hard edge, so existing definitions are unchanged.     • Tighter client protection from a hostile/broken server: caps on network packet sizes (effect params, definition/curve sync), vfx_sync packet version check, cap on effect duration from the server, instance-id validation on stop.

    v13¶

    • Datapack VFX effects and curves sync with dedicated-server clients (the vfxweaver:vfx_sync packet on join and after /reload) — custom effects now play for players on a dedicated server, like in single-player.

    v12¶

    • sendEffect accepts a direct world position — no pos_x/y/z hack (the client immediately re-anchors spatial bindings to the point).
    • Custom easing curves: files data/<ns>/vfx_curves/<name>.json or an inline object { "curve": [[t,v],...] } in any easing field.
    • Param multiplier: "param": { keyframes/start-end/constant/binding + "multiply": { "bind": "proximity", ... } } — final value = base × multiplier (e.g. an animated dent fading with distance from a point).
    • VFXAPI.playEffectId(...) returns the instance id, VFXAPI.stopEffect(long) stops one specific instance; sendStop(player, effectId, instanceId) — over the network.
    • Network protocol version 4: the packet carries an optional position and instance id.
